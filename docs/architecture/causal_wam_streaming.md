# 因果 WAM 连续反馈执行设计

2026-11-11。此设计延续[项目目标](../../plans/v0.0.1/goals/036_project_goal_20261023.md)
和[仓库结构设计](repository_design.md)。当前[两窗口实验](../../reports/tracking/joint_control/causal_wam_two_window_feedback_20261111.md)
已通过实际反馈及独立重放，但两次模型生成与物理执行分进程、按固定短窗衔接；
前 80 周期使用正确参考历史，末尾连续任务成功仅 9 个端点。它尚不是完整在线
WAM 闭环，也没有达到 40 端点稳定门槛。

下一阶段建立可持续、可审计的重观测执行路径，避免每增加一个窗口就复制一套
实验脚本。设计必须保留相同机器人、控制接口、坐标系、TCP、单位、mask、20 Hz
控制周期和既有安全/质量门；不把几何重建或模型预测精度等同于实际控制成功。

## 进程与数据流

```text
owner：冻结配置/来源、启动并等待自己拥有的进程、记录预算和失败
  ├─ CPU/OSMesa 仿真进程：当前图像 + 实测状态 → 参考绑定 → 反馈控制 → 下一实测状态
  └─ GPU 模型进程：当前图像 + 任务 → 固定 WAM → 40 个期望 TCP/opening 端点
```

owner 只创建一对继承的本地 socket 端点交给两个子进程，不提供公网监听；消息采用
有界长度、明确版本和完整读取的帧，处理分片、对端关闭和超时。仿真与模型分别
写入各自独占的仓库 `outputs/` 子目录；仿真进程仍保持空 CUDA/LD、OSMesa 和现有
写路径限制，模型进程显式指定用户授权的 GPU UUID 与空 LD。checkpoint、Cosmos
快照和发布数据只读。父进程只可停止并实际 wait/reap 自己启动的子进程。

## 每个窗口的不变量

1. 仅在上一个动作及全部 25 个内环采样完成、控制器和夹爪无待提交事务时采集
   当前双相机图像、实测 TCP/opening、仿真时间及状态 SHA。渲染前后状态和时间
   必须一致。第一个窗口使用明确登记的当前历史，不读取未来专家或任务标签。
2. 请求只包含递增请求号、当前控制步、当前图像引用及 SHA、当前状态/时间绑定、
   公开任务文字和固定采样参数；模型可见的内容仅是当前图像和任务文字。禁止
   注入未来 RGB、正确参考、物体特权状态或任务成功谓词。
3. 推理期间仿真不得积分或派发动作；记录等待前后状态 SHA、仿真时间及墙钟耗时。
   本阶段允许暂停仿真时间，不能据此声称真实实时能力。响应必须匹配唯一请求号、
   步号、状态和图像 SHA，满足有限 H40、Action128 有效槽、seed 和模型身份；
   乱序、重复、陈旧或不完整响应均不得用于控制。
4. 以请求时的实测 TCP 为 anchor 解码当前已生成参考，只向当前八周期反馈策略
   提供该参考。每步依据当前测量和已完成历史选择 action，实际完成后才提交
   机械臂、夹爪和内环历史。下一窗口通过现有
   [连续边界](../../src/s2a/research/joint_control/preview/streaming_feedback_boundary.py)
   切换，保留 latch、上次命令、warm start 和历史，不得跨独立评估复用状态。
5. 任何质量 witness 缺失、关节缓冲损失、模型/通信错误或身份不匹配都保留已
   派发动作与实际步数，在下一次派发前停止；不静默重试、换参考或扩大预算。

请求、响应、图像、实际状态、命令、内环 q/qvel/时间、模型 mask 与去噪 ledger、
源/权重/配置 SHA、进程退出和 GPU 释放各自留痕。成功与失败都写独立结果；
模型服务不能读取评估器的未来轨迹或使用 task-success 决定控制。

## 分阶段执行与证据边界

1. **协议和生命周期。** 先用 CPU 模拟服务和实际 socketpair 测试有界帧、分片、
   乱序、重复、超时、断连、错误传播、子进程实际 wait/reap 和 fail-closed，
   不启动模型或物理仿真。验证引用路径和状态绑定只接受当前登记的数据。
2. **流式仿真适配。** 在 CPU mock 下测试跨多个八周期窗口的因果数据流、事务和
   状态隔离；旧 8/16 周期运行入口及其历史 SHA 必须保留，新的长预算需要显式
   准入，不能靠修改历史输出或放宽旧阈值获得资格。独立 checker 只重放实际命令。
3. **真实模型准入。** 另行预登记固定模型、设备、最大请求/去噪、仿真与物理
   预算和停止规则。首两个窗口必须复现已审核的 step80/88 参考、状态与图像；
   不匹配时停止，不能把新的不同轨迹包装成原因果证据。各子进程及 GPU 使用
   均需完整退出和资源释放记录。
4. **有限连续开发实验。** 首次候选可登记至多 48 个新控制周期（六个 H40 请求，
   每请求 35 次去噪），以检查能否覆盖 40 个连续末端任务谓词；完整预算和实际
   结果另行报告。该实验仍从已研究初态和正确参考前缀出发，不是最终留出验收。
   之后才可在统一候选下依次完成原 18 条正确参考、12 条 WAM 开发和 24 条留出
   初态，保留总体至少 20/24 且各任务至少 4/8 的原门槛。

模型推理可能远慢于 0.4 秒的八周期窗口；独立记录墙钟延迟与暂停物理的假设。
实时连续控制、跨任务泛化和真机均需独立验证，不能由有限短窗推断。
