# 分支 WAM 反馈：回放比较修复后的单次验证

2026-11-11。首次物理继续阶段因内存 NumPy 数组与已发布 JSON 列表的比较类型
不一致，在两个分支均重放到 step120 后失败；详见[失败报告](../../../../reports/tracking/references/early_tabletop_live_feedback_failure_20261111.md)。
两次各完成 3,000 个内步、没有派发新 WAM 参考动作，实际 wait/reap；原失败结果
保留，不能计作成功或当作零成本。

修复仅把内存回放经既有严格 JSON 序列化转换后交给原比较器，不改数值、容差、
控制器、夹爪规则、目标或实验停止条件。另用一个新的输出目录执行**一次**
物理反馈验证：继续使用此前两个分支各自的已审核图像和已生成 WAM 响应，先
完整重放至各自 step120，重新核对状态和当前图像，再各执行最多八周期及各自
独立 checker；不加载或重新请求模型。两个分支的来源、参考、状态和误差分开
报告，checker 只重放已派发命令且不声称验证策略或停止理由。

本次修复验证最多两次 producer 加两次 checker，每次 128 周期、3,200 内步，
共最多 12,800 个新增内步和 16 个新选择命令；本轮 GPU/模型调用为零，所有
worker 实际 wait/reap。将前一采集阶段 12,000、失败阶段 6,000 和本次至多
12,800 一并计算，整次实验总上限 **30,800 内步、20 个新选择命令、30 次
native 模型和 30 个软件 context**；此前两次 WAM 请求和 70 次 denoise 仍为
总量，不增加。启动前固定新配置、来源、零工作 dry 和 32 并发专项；不自动
重试，不覆盖历史产物，失败和提前停止按实际记录。

这仍是一个开发初态上的短窗口对照，不代表 600 周期闭环、18/12/24 留出
资格、实时性或真机结果。参考本身改变后，两分支误差不能直接归因于某一层。
