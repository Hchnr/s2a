# 三任务共同固定 H40 的复位开发对照

2026-11-13。统一自适应开发矩阵的前四条在质量停止前未记录目标 grasp；已收到的
夹爪强闭合参考有 118 个端点均位于未消费后段。既有一个碗任务探针显示固定消费
H40 可使参考闭合实际发生，但单案例不能证明其他任务安全或成功。登记本次共同
对照，以判断延长参考消费是否值得进入后续 600 周期的真实当前图像闭环。

## 固定协议

按[配置](../../../../configs/tracking/references/reset_multitask_fixed_h40_20261113.json)
固定六个旧开发案例：三个任务的 init0，各用 seed 42/43。每个案例从实际 reset
先执行并核对已有首 8 周期，再从本次复现的 step8 当前图像使用原矩阵实际产生、
已核验身份的同 task、同 seed、同 checkpoint H40 响应，逐个消费最多 40 周期。
不再请求世界模型；每 8 周期切换控制分段，保持实测反馈和夹爪历史。最后分段的
预览需要超出 H40 时明确记录末端保持，不把保持值称为模型预测。

沿用固定控制器、TCP、20 Hz / 2 ms、质量 witness、关节缓冲及停止条件，不读取
任务成功或物体真值作为在线输入。出现任何保护停止即记录实际派发周期，不调低
门槛或自动重试。独立 checker 从同一 reset 重采 step8 图像，解码相同参考并仅重放
实际命令；不加载候选、不重算质量停止。各案例保留原矩阵 producer 失败、来源、
原控制动作和后置独立重放，不能将失败 owner 改写成成功。

每条每相位最多 48 控制周期、1,200 内步、3 个仿真模型和 3 个 OSMesa context；
producer 与 checker 全六条合计最多 576 周期、14,400 内步、36 模型 / context。
最多四案例并发，CPU/OSMesa 空 CUDA/LD、数值库单线程、各 worker 独立输出并
逐个实际 wait/reap。复用原 step8 已有响应，不新增模型初始化、去噪或最终留出。

记录每条实际消费的生成端点、参考及实测夹爪、目标 grasp、原生任务谓词、
位置 / SO(3) 前向误差、内环关节余量和停止原因。与原自适应分支按案例报告
实际已执行时长及证据，不能将两个不同参考的跟踪误差当作单因素任务效果；短于
48 周期的停止保留，不补齐或替换分母。达到 48 周期也不等于 600 周期稳定成功。
本试验仅作开发筛选，不能替代当前候选的正确参考正控、12 条开发闭环或 24 条
新初态验收；若 H40 保留表现改善，下一步仍需同一候选的长时程当前图像对照。
