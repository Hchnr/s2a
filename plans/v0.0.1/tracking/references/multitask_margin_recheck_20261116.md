# 三任务双 seed 首次 WAM 刷新点的当前状态重算

2026-11-16。一次 bowl / seed43 的已重放状态对照表明，暂缓 step17 的一次
余量刷新后，当前实测状态可求出并执行一个额外合格动作，但下一周期再次要求
刷新，不能外推。现从[原六条 WAM 开发轨迹](../../../reports/tracking/references/reset_multitask_adaptive_complete_20261113.md)
各自的**首次质量刷新信号**构造同一规则的非盲短窗，覆盖三个旧初态及 seed
42/43。首次信号由既有日志事后确定，配置固定为 step `26, 17, 143, 17,
17, 17`；其中 wine / seed43 是 `no_audited_second_pose`，保留为不得延期的
对照，其余五条为 `quality_margin_consumed`。不筛除停止、缺失或失败案例。

每条从 reset 重新计算至对应信号前的真实动作，逐周期核对已执行命令、实测
状态、TCP、25 内步、夹爪和原生评分；各已使用参考都必须绑定当时实际重采
的图像、原请求与实际模型响应、原 seed、实测 TCP 和时间。在线动作只接收当前
实测状态、已完成历史和当时已经生成的 H40；不读取信号之后的实际动作、图像、
状态或任务标签作为输入。原日志仅用于事前确定本非盲测试起点及前缀一致性。

在每个信号处，若已完成动作实际 pose 或关节缓冲失格则不派发；只对首次
`quality_margin_consumed` 信号暂缓刷新一次，以当前实测状态及同一 H40 重算
原控制决策，最多额外执行 **1 个**通过原动作 / 速率 / 关节 / 制动与独立
witness 的周期。无 witness 则不派发；缺少审核第二点仍立即停止。完成一个
额外动作后无论其结果如何均停止，不使用之后原轨迹的模型响应，也不预测未来
的重观测收益。该试验有意改变一次刷新时机，须逐例记录模型预测与实际误差、
止因、超限和原生任务标签，不声称单步通过意味着真实安全或最终成功。

独立 checker 从同一 reset 重放每条实际动作并重采每个已用参考图像，逐值比较
命令、状态、TCP、内步和夹爪；checker 不加载候选、也不重算求解或停止原因。
每阶段原前缀共最多 237 周期、五个可延期案例最多各额外 1 周期，即最多
242 周期 / 6,050 个 2 ms 内步；6 个 CPU worker、18 模型及 18 个 OSMesa
context。每次决策沿用 480 baseline / 320 quality 响应及原夹爪、独立 witness
预算。前缀不符或任何来源失败保留失败和实际开销，不自动重试。

先进行相关 64 并发 CPU 回归、严格来源核验和零物理预检；每个 worker 使用
独占目录并实际 wait/reap。新 WAM / GPU / fresh 均为 0。这不是 600 周期 WAM
开发矩阵、正确参考资格或 24 条最终留出，不能凭单步改善声称稳定完成总目标。
