# 优先保留刷新余量的因果候选

2026-11-15。六条旧开发轨迹的事后扫描共发现 119 次
`quality_margin_consumed`；每次已有预测都落在位置 `0.0095 m` 或旋转
`0.047 rad` 的规划边界 `1e-10` 范围。规划器允许前两点到该边界加容差，
刷新条件却在边界减容差时触发。该观察提示一次新参考可能消费一步即要求再次
刷新；不是控制误差概率，也不证明所有边界候选都有更好的可行替代。

## 候选设计

原 `margin_two_step_search` 已收集本次求解中实际评价、通过原线性关节约束且
通过原两点 pose 余量的候选。提供一个显式实验选项，只在这批候选中优先选择
第二点预测同时满足位置 ≤ `0.00925 m`、旋转 ≤ `0.0455 rad` 的候选；这些值
是在既有 `0.0095 m` / `0.047 rad` 刷新边界内，分别多留 `0.00025 m` /
`0.0015 rad` 的固定探索余量。门限不按任务或结果扫描，也不改变实际验收。

有满足探索余量的候选时，仍按原 future slack、原目标值和原确定性键排序；无此
候选时严格回退原先选择。它不修改生成参考、首点约束、0.01 m / 0.05 rad pose
门、命令 box / 变化率、0.05 rad 关节缓冲、任何 fallback 或质量 witness 独立
审核，不新增模型 rollout，也不输入对象状态或任务标签。默认行为与原选择逐值
一致；探索选项只在明确配置的试验中启用。

## 验证顺序

1. 从六条已记录 producer 重算全部已完成周期的刷新信号和其第二点预测，按案例
   保留原分母、source SHA 和原失败收据；这属于观察后的回顾分析。
2. 单测验证优先级、无候选时逐值回退、原安全边界、预算和因果输入；在同一固定
   几何与 controller 输入上核对候选与原求解的响应次数及独立 witness。
3. 复用 bowl/seed 43 的 reset 和已生成参考，在同一实际端点 16 比较默认候选与
   探索候选；前 16 周期仍严格重现原动作与实际状态。若本次缓存没有符合探索余量
   的候选，报告无替代，不虚报改进；不改变未来模型参考或构造反事实动作。
4. 如成功选择不同候选，维持相同的逐步质量 / 物理停止条件执行有界短窗，并由
   不加载候选的 checker 从 reset 独立重放；逐步报告两条同时刻参考误差、实际
   状态、安全余量、grasp 与任务谓词。不得把单案例短窗或预测改善当作任务成功。

任何实际运行先冻结输入、代码与预算、完成相关 CPU 并发回归及零物理预检；
按需复用已有 WAM 输出，暂停物理等待时钟，不使用最终留出初态。完整正确参考
18 条、WAM 开发 12 条、最终留出 24 条，以及实时和真机要求保持不变。
