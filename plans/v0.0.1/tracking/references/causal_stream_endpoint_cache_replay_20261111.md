# 复用已验证端点的 CPU 物理回归

2026-11-11。独立诊断复现 step120 重复端点读取造成的物体四元数浮点变化，
见[诊断报告](../../../../reports/tracking/references/causal_stream_endpoint_diagnostic_20261111.md)。
候选在每条已完成动作取得端点时缓存该次实际采样；同一步再次请求端点时，只有
当前完整原生状态 SHA 和时间逐位一致才返回缓存，否则立即报错。不修改仿真状态、
不归一化或放宽状态哈希；不同步必须获得新的实际采样。

先在 CPU 假环境覆盖重复调用会改变状态、状态/时间改变时拒绝复用、跨窗口
完整反馈与独立重放。然后一次 CPU/OSMesa 物理回归：使用同一失败 producer 的
80 条前缀与 40 条实际完成动作，最多 3,000 个 MuJoCo 内步，逐周期核对命令、
完整状态、25 个内环采样和任务标签；重放结束后从已验证 step120 状态捕获一次
当前双相机图像，并核对渲染前后状态与时间未变。失败 producer 的 stop 仅在重放
中构造并明确标记，不声称原运行正常停止。

本次不初始化 WAM、不发模型请求、不选择新动作、不引入新初态、不自动重试；
原试验及诊断产物保留。零物理 dry 与目标 CPU 回归必须在启动前通过；所有子进程
实际 wait/reap，输出只写仓库。成功只能证明这 40 条动作的回放和 step120 捕获，
不能证明第六个 WAM 窗口、40 端点稳定、实时性、留出泛化或真机结果。
