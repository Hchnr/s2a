# 已生成参考执行窗口的限定因果诊断

目的：检验部分失败中生成的闭合事件是否因只执行8步而被丢弃；不将此假设推广到没有生成闭合/释放的案例，不修改原5/6开发及最终20/24稳定门槛。

使用已完成的8条开发案例，不读取fresh。每条按固定规则选最早“当前开度>0.8且40步参考含开度<0.2、最早闭合索引>=8”的查询；不存在则记为无此诊断事件，不补选其他任意时刻。选择仅用于离线诊断，不能作为生产按任务选择策略。

在各自原初态重放保存命令至该查询的端点，核对原始状态SHA、控制器缓存和motor目标。两分支从相同状态/缓存/随机状态出发，使用同一已生成40步参考：A执行原前8步；B执行完整40步。观察同一共同前8步是否一致，并独立记录B后32步。B只用当时已生成参考和当前机器人反馈；不额外调用模型、不重新取未来图像参考、不提供对象状态或任务谓词给控制器。

控制算法、目标解码、夹爪逻辑不因案例改变。若接入新零空间QP，先验证固定正确参考回归资格；当前尚无该物理资格，不能把代数533条回归当作已完成。诊断也可以先用原已冻结控制器，并将任何数值异常作为失败保留，不在运行中替换求解器。

记录约束、位置/旋转跟踪、实际开度、原native抓取接触/物体位移及任务谓词；对象指标只作事后证据。B抓取/成功不算原600步任务或fresh成功，且更长开环窗口可能恶化位姿误差。没有显著效果则保留失败，不追加窗口扫描。这个对照不检验重新规划后的完整600步政策，只隔离已生成chunk的事件执行。

本文件为诊断合同，尚未实现或执行分支对照。原数据生成的所有失败、未执行项和额外预算继续单独保留。
