# 开发轨迹中的抓取与释放预测重规划一致性

2026-11-10。质量恢复短窗未超过已有候选，不能继续以同一少量端点的位姿优化代替
任务改进。以已独立复核的v4全部12条开发轨迹，检查相邻已生成参考是否在同一绝对
时间持续表达闭合/打开阶段，以及这些阶段的位姿是否一致。原目标、18正确参考、
12开发、24最终留出和GPU禁令均保持。

## 数据与诊断口径

固定使用已独立审核的三个任务、每任务一个开发初态、seed42/43及raw/terminal058
共12条记录；每条600控制周期、75个H40生成chunk、每8步重规划。依独立审核SHA
读取完整chunks及实际steps，逐周期核验已执行opening与所属chunk相应索引一致，
重新核对来源前后身份。只读取本仓库已有开发数据，不读取final fresh。

每条连续相邻chunk有74对，共888对；旧chunk的第8..39点与新chunk的第0..31点
对应相同绝对时间，共28416个重叠目标。报告相同端点的开度差、TCP位置与SO(3)
角差，以及旧闭合/新打开或旧打开/新闭合的点数。开度`<0.35`与`>0.8`只作描述性
状态分区，沿用此前闭合和开度分析口径，不是策略门槛或抓取/释放成功判据。

对旧chunk的首个闭合（或打开）目标若位于前8步之后，比较其预测绝对到达时刻与
新chunk首个同类目标：提前、相同、推迟或新chunk不再预测。保留新chunk中的完整
40点，后8点虽超出旧chunk重叠窗口，仍可表明新预测推迟；若新窗口无同类目标，
仅记作该窗口未见。事件没有身份标签，两个首个目标不保证是同一次真实物理事件。
另外统计当前实测开度仍分别处于打开/闭合区间的子集，以减少持续闭合或打开造成的
混淆，但不把该子集当独立样本或因果验证。

在旧预测事件对应的同一绝对时间，报告新旧目标TCP是否分别满足此前参考保留候选
的0.02 m/0.1 rad**描述性位姿一致性尺度**；同时报告整个下一次执行8点前缀是否
满足该尺度，以及当前实测TCP相对旧前缀首点是否满足0.03 m/0.15 rad描述尺度。
这些固定尺度仅用于判断可进一步研究的覆盖情况，不证明安全、可达、正确语义或收益。

## 边界与执行

同时保留每案例实际任务/grasp计数以解释阶段，物体与任务真值只作事后描述，不能
进入在线候选。本次不求解、不生成控制命令、不初始化仿真模型、不推进物理、不调用
WAM、不拟合、不消费final fresh；使用显式空CUDA/LD和单线程数值库。每案例独占
outputs目录，最多12个CPU worker，每个实际wait/reap且不自动重试；源和输入指纹
前后核对，失败及部分输出保留。先做时间对齐、边界、旋转、异常值和来源检查，完成
32并发CPU专项和dry后冻结源码。结果只能决定下一项需验证的因果假设，不把回顾
统计、相似位姿或阶段变化当实际跟踪、抓取、任务成功或泛化证据。
