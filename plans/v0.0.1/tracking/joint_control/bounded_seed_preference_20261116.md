# 缓存 seed 优先排序的未来质量增量上限

2026-11-16。原 18 条正确参考中，seed 优先候选为 16/18，旧候选为 14/18；
前者的 case 07 在第 86 周期前因质量无 witness 停止，case 12 末段不稳定。
此前 18 条轨迹各自首次改变排序时的已记录 seed 与默认计划之间，后六点归一化
预测质量 slack 增量最大为 `0.299054`。case 07 停止前的部分计划增量超过 3；
其他成功案例也出现过大增量，轨迹回顾不能证明这些选择导致失败。

登记一个**默认关闭、全任务相同**的探索性候选：在既有合格缓存中，当前因果
计算的八周期 seed 只有在其后六点最大归一化质量 slack 比原排序结果高不超过
`0.3`（加既有 `1e-10` 比较容差）时才优先，否则选择原排序结果。上限取自
首次已记录分歧最大值向上取整，以保留那些观测到的首次选择并限制更大的预测
退化；这是使用了开发数据的非盲设计，并不保证新轨迹中再次选择相同 seed，
也不是实际运动或安全保证。默认结果本身可有非零 slack，上限只约束相对增量。

只在已经求值、关节 / 制动 / 速率及前两点余量合格的候选中改变排序，原独立
witness、fallback、因果刷新、动作限幅和响应预算不变；不读取历史动作、未来
实际状态或任务标签。记录 seed 是否可选、额外 slack、是否被上限阻止、实际
选择及模型响应；上限筛选不产生额外模型响应。对空缓存、越界、无 seed、相等
边界及默认策略隔离做有意义的单元验证。

按原 18 条、原初态 / seed / 控制器 / 参考 / 周期长度从 reset 统一执行，
每条已闭合 producer 独立重放；复核动作、实际状态、所有 25 内步、TCP、夹爪
和任务标签，checker 不重算停止原因。资格仍要求完整执行、末 40 周期成功、
位置 / 旋转 RMSE 不超过 `0.01 m / 0.05 rad`，且没有内步低于 `0.05 rad`
关节缓冲。分别与 14/18 原排序及 16/18 无上限 seed 排序比较；记录所有失败和
原分母，不能据此声称最终任务达标。

每阶段最多 18 个 CPU worker、54 模型及 54 个 OSMesa context，4,907 控制
周期 / 122,675 个 2 ms 内步；每次至多 480 baseline / 320 quality 模型响应
及 `3^8` 夹爪候选，独立 witness 另外按实际计费。先完成 64 并发相关 CPU 回归
