# 优先保留已审核原计划的统一候选对照

2026-11-16。18 条正确参考中当前候选为 14/18。对四条失败案例首次动作
分歧的探索性冻结状态核对显示，原控制器计划也存在于当前搜索已评价的候选缓存，
并满足该时刻的双点 pose 余量、关节、变化率及制动约束；当前排序选择了预测
后续误差更小的另一计划。原计划的后续预测 slack 更高，这些旧状态结果并不
证明重新执行会成功。

新增**默认关闭、单独启用**的统一候选：若原 refiner 当前产生的完整八周期
seed 已在本次搜索的已评价缓存中，且通过原有 joint / braking / rate 与两点
margin 筛选，则从同一个合格集合中优先选择与 seed **逐值相同**的计划；否则
保持原排序和原 fallback。候选仍须经过既有独立 witness 审核和因果质量刷新，
不增加响应评估、不放宽首两点、命令或关节硬约束。此变体改变的是合格候选的
排序，可增加未来六点的软质量 slack；逐周期记录原排序与新选择的差别和 slack，
不能把模型预测当作真实状态安全保证。任何原计划只是当前状态下实时计算的
seed，不能读取历史专家动作、未来实际状态或任务谓词。

先用人工数据和已记录冻结状态验证缓存选择、fallback、独立审核与原始 320
响应预算；原默认策略和历史源码保持不变。再对原 18 条正确参考统一启用同一
变体，从各自 reset 重新执行并独立重放，不复用旧候选动作；沿用原初态、seed、
控制器、TCP、参考、案例长度及 18 条分母。完整资格仍要求每条完整执行、最后
40 周期任务成功、位置 / 旋转 RMSE 不超过 `0.01 m / 0.05 rad` 且不丢失原
`0.05 rad` 内步缓冲。分别与原 14/18 候选及历史正控比较，保留所有停止和
不满足条件的案例，不按任务挑选排序。此设计是基于开发结果的非盲对照。

producer 与 checker 各最多 18 个 CPU worker、54 个仿真模型 / OSMesa context，
4,907 周期 / 122,675 个 2 ms 内步；每次选择仍最多 480 baseline / 320 quality
响应及 `3^8` 夹爪候选，独立 witness 成本按实际登记。子进程各自独占目录、
实际 wait/reap，不自动重试；失败收据与原分母保留。先完成 64 进程相关回归及
