# 质量约束求解的固定状态CPU耗时剖析

2026-11-11。[两因素报告](../../../../reports/tracking/joint_control/causal_event_bridge_factorial_20261111.md)
中的单周期臂决策约1.04–1.17秒，超过固定20 Hz接口的50 ms周期。该计时覆盖
多个环节，不能预设瓶颈。本阶段只测既有质量求解器和其独立witness审核，不更改
求解、约束、阈值、候选或物理行为；目标是确定可复现的热点，为后续等价加速提供
依据，而不是把离线速度、单步witness或合成结果当实时控制成功。

固定同一已审计task1 seed42开发记录中step352、355、359这3个已有实测输入；每点
仅使用该时刻的q/qvel、SITE、固定M/J和控制器参数、已完成的上一条命令、已有8步
seed计划，以及step352已经生成的同时间H40参考。按原接口与SO(3)约定构造模型和
参考；`initial_joint`采用已记录的重放runtime值，不能声称它是未保存的历史内部值。
原始25个内环预测误差历史在这些记录中不可得，固定零误差仅用于耗时诊断，不能用
作实际安全或控制授权。该三个时间点互相关联，不能代表跨任务或新初态分布。

每点使用相同输入执行两次现有求解：一次不带profiler计时，一次带`cProfile`记录
调用数、self time和累计时间；逐项比较状态、响应数、约束、witness及计划。若有
witness，对其执行原独立审核并记录结果；无witness保持原停止，不重试。分别记录
建模、求解、审核墙钟及实际资源计数，profiler引入的开销和共享机器负载另作说明。
本阶段不计完整控制器周期，不推断优化后的速度或物理任务效果。

三个CPU worker各独占目录、实际wait/reap，最多6次求解和960次原有限响应、3次
独立审核；先做32并发专项、Ruff和零模型dry，输入/源码/配置/资产前后核SHA。
空CUDA/LD、数值库单线程；无新物理步、WAM、GPU、拟合或final fresh。任何优化
必须单独登记，保留原求解域、约束和独立审核，并在相同输入及实际控制中验证。
