# 同状态机械臂动作的正确参考短窗对照

2026-11-16。事后诊断发现 case 03 在相同夹爪命令下，当前候选与原正控的
物体轨迹大幅分离，但两条原轨迹的状态和机械臂动作都不同，不能仅凭相关性
判断作用。本试验针对该已见失败案例，在候选轨迹的分歧前状态做一次受限的
固定动作序列对照；不是最终验收或盲测。

两支均从原 reset 重放当前候选的前 40 个实际动作，并逐周期核对原已独立重放
的状态、内步和夹爪缓存。到 step 40 时比较两支的完整观测端点、控制器缓存和
夹爪 motor 状态。随后 16 周期保持同一个正确参考和逐周期相同的原候选夹爪
命令：一支继续重放候选机械臂命令；另一支使用原成功正控的对应 16 条机械臂
命令。后者来自另一条历史轨迹，属于固定的离线诊断动作，不是在线决策或候选
策略。预检要求每条命令在原 box 内、从候选第 39 步实际命令开始的机械臂变化率
不超过 0.25，且两条历史夹爪命令一致；原目标、工具和初态身份不变。

两支均记录 16 个实际 TCP 误差、目标物体位置、grasp / 任务谓词及每周期 25 个
关节内步。物体位置和任务标签仅用于事后评分；不参与派发。每一步后检查原
`0.05 rad` 关节缓冲，若已丢失则不再派发下一动作；记录已发生的内步与所有
pose 误差，不把短窗结果算作任务资格。独立 checker 从 reset 重新重放两支实际
动作、核对端点、内步和夹爪；候选动作支须同时复现此前矩阵的同段实际轨迹。

每阶段最多 2 个 CPU worker，各 56 周期 / 1,400 内步、3 个模型与 3 个 OSMesa
context；producer 与 checker 合计最多 224 周期 / 5,600 内步。动作固定、WAM 0、
GPU 0、新留出案例 0；所有 worker 独占输出、实际 wait/reap，不自动重试或
覆盖。先完成来源与动作约束的零物理预检及 CPU 回归。最终只比较该分支状态下
两段动作的后果，不将历史动作直接部署，也不推断 18 条或 WAM 的总体改善。
