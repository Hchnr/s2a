# 已生成参考与桌面的静态几何核查

2026-11-11。[实际力矩与接触重放](../../../../reports/tracking/response_models/replayed_contact_torque_20261111.md)
显示同一开发初态的夹爪从 step120 开始接触桌面，随后发生力矩裁剪和模型失配。
为确定是否需要改动参考层，检查当时已生成的 TCP 目标在当前夹爪配置下是否与
固定桌面几何相交；这项检查是离线几何证据，不是在线策略或物理可达性证明。

固定[配置](../../../../configs/tracking/response_models/reference_table_geometry_20261111.json)
的历史 producer、checker、力矩审计与计数校正。对 step80–125 共 46 个已执行
动作及 step126 已记录停止前状态，分别读取该决策时已完成的实际状态与当时已
生成的参考目标。step80 当前状态来自已核验的原 80 周期前缀终态；其他状态来自
上一周期实际端点。step126 的目标已包含在 step120 生成的参考中，但该动作未派发。
不读取任务成功标签作为选择或几何输入，不使用未生成的参考或未来状态。

对每个状态，先在原配置下重建碰撞几何，再只为静态查询将固定机器人基座刚体移动，
使原 controller site 对齐 `desired_tcp @ inverse(site_from_tcp)`；关节和当前
夹爪配置保持固定，桌面及对象位姿不得改变。验证被查夹爪几何的刚体变换与目标
转换一致、TCP 对齐误差及 qpos 变化，分别记录实际当前和目标代理下夹爪—桌面
碰撞点及非正距离。该代理不解 IK、不推进物理、不改变原参考，也不把未来夹爪
开度或对象特权状态用作在线输入；当前开度与动作完成后的开度可能不同。

最多一个 native 模型、94 次 `mj_forward`（47 个状态各恢复和对齐一次）、零
物理积分、零 WAM/GPU 调用和零新初态。禁止 `mj_step*`，限定实际 `mj_forward`
计数，保存输入/源码 SHA、完整结果及子进程实际 wait/reap；失败保留、不自动
重试。先执行零模型 dry 与 32 并发相关测试。静态相交只能说明当前夹爪配置的
该目标代理存在几何冲突；不能推断原机器人 IK、实际连续路径、未来接触力、
完整任务或最终 18/12/24 留出验收。下一步只有在明确原参考误差和安全代价后，
才可登记因果参考干预并在独立物理反馈中对照。
